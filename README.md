# Практика

Светлый интерактивный frontend-прототип сервиса для подготовки к экзаменам, собеседованиям и другим проверкам знаний. Приложение работает на mock-данных и готово к последующему подключению Spring Boot backend.

## Технологии

- React 19;
- React Router 7;
- Vite 6;
- обычный CSS без UI-фреймворков;
- `localStorage` для демонстрационного сохранения прогресса.

В проекте нет backend, API, Redux и настоящей авторизации.

## Запуск

Установить зависимости:

```sh
npm install
```

Запустить dev-сервер:

```sh
npm run dev
```

По умолчанию приложение открывается по адресу [http://127.0.0.1:5173](http://127.0.0.1:5173).

Проверить production-сборку:

```sh
npm run build
```

Открыть собранную версию локально:

```sh
npm run preview
```

## Точка входа и состояние

### `src/main.jsx`

Минимальная точка входа. Она:

1. находит элемент `#root`;
2. создаёт React root;
3. подключает `BrowserRouter`;
4. отображает `App`;
5. подключает общий файл стилей.

### `src/App.jsx`

Корневой компонент приложения. Здесь находятся:

- состояние прогресса по темам;
- состояние демонстрационной авторизации;
- данные текущего mock-пользователя;
- сохранение прогресса в `localStorage`;
- обработка оценок «Знаю», «Не уверен» и «Не знаю»;
- сброс прокрутки при переходе на другую страницу;
- общая компоновка с хедером, левым сайдбаром, контентом и футером;
- все маршруты приложения.

`App` передаёт страницам только нужные данные и callbacks. Страницы не обращаются к глобальному хранилищу напрямую.

### Интерактивные панели

`CourseDrawer`, `ContinueModal` и профильная панель:

- закрываются по кнопке, клику на затемнённую область или клавише `Escape`;
- блокируют прокрутку документа, пока открыты;
- возвращают прокрутку после закрытия.

Эту общую механику реализует `hooks/useBodyScrollLock.js`.

### Dropdown-компоненты

Dropdown выбора курса и фильтр сайдбара:

- используют собственное меню вместо системного `select`;
- показывают текущий выбранный вариант;
- закрываются после выбора, по `Escape` и по клику снаружи;
- возвращают фокус на кнопку после выбора;
- содержат `aria-expanded`, `aria-selected` и роли listbox/option.

## Авторизация

`pages/AuthPage.jsx` содержит два режима:

- вход: почта и пароль;
- регистрация: почта, пароль, повтор пароля и никнейм;
- тестовый вход без заполнения формы.

Переключатель входа и регистрации использует движущуюся оранжевую плашку с объёмным состоянием. При смене режима форма и информационный блок плавно меняются местами.

Проверки формы выполняются только в браузере:

- пароль должен содержать минимум 6 символов;
- пароли при регистрации должны совпадать;
- никнейм должен содержать минимум 2 символа.

Авторизация не сохраняется. После обновления страницы снова появляется экран регистрации. Старые ключи входа удаляются при запуске приложения.

## Курсы и темы

Все mock-данные находятся в `src/data.js`:

- `courses` — информация о курсах и список связанных тем;
- `topics` — описания, начальный прогресс, конспекты и пары вопрос/ответ;
- `topicById(id)` — поиск темы;
- `courseForTopic(id)` — поиск курса по теме;
- `average(values)` — расчёт среднего процента.

Обложки задаются путями вида `/images/java-course.png` и физически лежат в `public/images`.

## Тренировка

Страница `TrainingPage` формирует колоду карточек в зависимости от query-параметров:

| Параметр | Результат |
| --- | --- |
| `?topic=core` | Карточки одной темы. |
| `?course=java` | Все карточки выбранного курса. |
| `?mode=weak` | Слабые начатые темы из всех курсов. |
| `?course=java&mode=course-weak` | Темы выбранного курса с прогрессом ниже 50%. |

На карточке всегда доступны три оценки:

- **Знаю** — `+5` пунктов;
- **Не уверен** — `−2` пункта;
- **Не знаю** — `−7` пунктов.

После оценки открывается следующая карточка. Значение темы всегда ограничивается диапазоном от 0 до 100. Расчёт вынесен в `utils/progress.js`.

Кнопка **«Показать ответ»** раскрывает правильный ответ, но не обязательна для перехода к следующей карточке. После завершения отображается количество ответов каждого типа и возможность пройти тренировку повторно.

## Прогресс и хранение данных

Прогресс хранится в `localStorage` под ключом:

```text
practice-progress-v1
```

Формат данных:

```json
{
  "core": 82,
  "collections": 64,
  "threads": 38
}
```

Общая готовность курса — среднее значение его тем. Это демонстрационная эвристика, а не полноценная модель адаптивного обучения.

## Стили и адаптивность

Все стили находятся в `src/styles.css`. Файл содержит:

- цветовые переменные;
- типографическую систему serif/sans/mono;
- кнопки и состояния фокуса;
- сетки страниц;
- анимации хедера и авторизации;
- карточки и боковые панели;
- desktop/mobile media queries;
- поддержку `prefers-reduced-motion`.

Левый сайдбар показывается на широком экране и скрывается при ширине меньше `1280px`. Основной контент ограничен шириной `1100px`, поэтому не растягивается бесконечно.

## Подключение Spring Boot

Для перехода с mock-данных на backend рекомендуется:

1. создать папку `src/api`;
2. вынести туда запросы курсов, тем, профиля и сохранения результатов;
3. заменить импорт данных из `data.js` на загрузку через API;
4. заменить `localStorage` в `App.jsx` серверным сохранением прогресса;
5. подключить настоящую сессию или JWT вместо локального `authenticated`;
6. оставить компоненты страниц без прямой зависимости от HTTP-клиента.

При размещении production-сборки Spring Boot должен возвращать `index.html` для неизвестных клиентских маршрутов, чтобы React Router мог обработать URL.

## Проверка интерфейса

`scripts/smoke.cjs` проверяет основные сценарии:

- переключение входа и регистрации;
- тестовый вход и непостоянную авторизацию;
- навигацию и скользящий индикатор хедера;
- фильтры сайдбара;
- dropdown выбора курса;
- обе выезжающие панели;
- модальное окно продолжения;
- тренировку и изменение прогресса;
- редактирование mock-профиля;
- отсутствие горизонтального переполнения на мобильных маршрутах;
- отсутствие ошибок JavaScript.
