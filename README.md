# Практика — Frontend

Документация frontend-части учебного сервиса для подготовки к экзаменам, собеседованиям и другим проверкам знаний.

**Часть проекта:** `Frontend`

## Текущее состояние

Приложение представляет собой работающий React-прототип с клиентской маршрутизацией, адаптивным интерфейсом и хранением пользовательского состояния в браузере.

Сейчас реализованы:

- вход, регистрация и тестовый вход;
- восстановление локальной сессии после обновления страницы;
- каталог из 3 курсов, 10 тем и 23 учебных карточек;
- конспекты тем и тренировки с тремя вариантами самооценки;
- прогресс по темам и курсам;
- история ответов, проблемные карточки и динамика знаний;
- личный кабинет с курсами и графиками активности;
- официальный каталог и демонстрационные курсы сообщества;
- адаптивный план подготовки с приоритетом слабых тем;
- светлая и тёмная темы, настройка размера текста и уменьшение анимаций;
- постоянные боковые панели на широком экране;
- fade-переходы между разделами и вертикальный Push-переход между курсами.

Backend и HTTP API пока отсутствуют. Авторизация, изменение пароля и пользовательские данные являются демонстрационными и работают только в браузере.

## Технологии

- React 19;
- React Router 7;
- Vite 6;
- обычный CSS без UI-фреймворков;
- `localStorage` для сессии, настроек, прогресса, активности и плана подготовки.

Redux, библиотека графиков и библиотека анимаций не используются. Графики построены на CSS и SVG, а переходы — на CSS keyframes.

## Запуск

Установить зависимости:

```sh
npm install
```

Запустить dev-сервер:

```sh
npm run dev
```

По умолчанию приложение открывается по адресу [http://127.0.0.1:5173](http://127.0.0.1:5173).

Проверить production-сборку:

```sh
npm run build
```

Открыть собранную версию локально:

```sh
npm run preview
```

## Точка входа и состояние

### `src/main.jsx`

Точка входа:

1. загружает сохранённые настройки;
2. применяет тему, размер текста и режим анимаций до первого рендера;
3. создаёт React root;
4. подключает `BrowserRouter`;
5. отображает `App`.

Предварительное применение настроек предотвращает светлую вспышку при загрузке сохранённой тёмной темы.

### `src/App.jsx`

Корневой компонент хранит и связывает:

- авторизацию и текущего пользователя;
- прогресс по темам;
- журнал ответов;
- активный план подготовки;
- настройки интерфейса;
- курс, для которого открыта настройка плана;
- выбранный тип и направление перехода между маршрутами.

`App` сохраняет изменения через функции из `utils`, обрабатывает оценки карточек, очищает данные при удалении аккаунта и передаёт страницам только необходимые props и callbacks.

Общий каркас после входа состоит из `Navbar`, левого `PopularCoursesSidebar`, центрального маршрута, правого `PreparationPlanSidebar` и footer. На странице профиля внутрь правого сайдбара дополнительно помещается `ProfileStudySidebar`.

## Главная и навигация по курсам

Главная страница рассчитывает количество курсов и тем, общий средний прогресс и список слабых начатых тем. Центральная карточка открывает `CourseDrawer`. Из панели можно открыть страницу курса или сразу начать тренировку.

Карточки в левом сайдбаре ведут непосредственно на `/courses/:id`. При переходе между курсами определяется положение выбранного курса в текущем фильтре:

- курс выше — Push-переход вверх;
- курс ниже — Push-переход вниз.

Обычные переходы между разделами используют одновременное затухание старой и появление новой страницы. Фон промежуточного слоя зависит от темы, поэтому в тёмном режиме нет белой вспышки.

## Авторизация и аккаунт

`AuthPage` содержит вход, регистрацию и тестовый вход. Клиентская проверка требует:

- пароль длиной не менее 6 символов;
- совпадение паролей при регистрации;
- никнейм длиной не менее 2 символов.

Сессия и пользователь восстанавливаются из `localStorage`. Редактирование имени и email в профиле или настройках обновляет сохранённого пользователя.

Смена пароля только проверяет форму и показывает демонстрационное сообщение: пароль не хранится. Кнопка «Выйти со всех устройств» фактически очищает локальную сессию текущего браузера, поскольку backend отсутствует. Удаление аккаунта после подтверждения очищает все ключи приложения.

## Курсы, темы и тренировки

`src/data.js` содержит 3 курса, 10 тем, конспекты и 23 пары вопрос/ответ. Вспомогательные функции:

- `topicById(id)` ищет тему;
- `courseForTopic(id)` определяет курс темы;
- `average(values)` округляет среднее значение.

Колода `TrainingPage` формируется по query-параметрам:

| Параметр | Результат |
| --- | --- |
| `?topic=core` | Все карточки одной темы. |
| `?topic=core&card=1` | Одна конкретная карточка темы. |
| `?course=java` | Все карточки курса. |
| `?mode=weak` | Все начатые темы с прогрессом ниже 50%, от слабых к сильным. |
| `?course=java&mode=course-weak` | Темы конкретного курса с прогрессом ниже 50%. |
| `?topic=spring&plan=java` | Тренировка темы, открытая из плана подготовки. |

Самооценка изменяет прогресс темы:

- **Знаю** — `+5`;
- **Не уверен** — `−2`;
- **Не знаю** — `−7`.

Значение ограничивается диапазоном `0–100`. После каждой оценки в журнал добавляются тема, индекс карточки, оценка, новый процент и время ответа. После завершения показывается распределение результатов и кнопка повторного прохождения.

## Прогресс и аналитика

Страница `/progress` позволяет выбрать курс и показывает:

- среднюю готовность курса;
- прогресс каждой темы;
- темы ниже 50%;
- две темы с самым низким прогрессом;
- до 5 проблемных карточек;
- историю знания выбранной темы.

Проблемные карточки сортируются по сумме ответов «Не уверен» и «Не знаю», затем по числу ответов «Не знаю» и дате последнего ответа. График динамики показывает до 8 последних записей выбранной темы.

На странице профиля первый график строится по реальному локальному журналу и фильтруется по курсу и периоду `1 / 3 / 7` дней. Недельный столбцовый график и месячная heatmap сейчас используют демонстрационные массивы внутри `ActivityCharts.jsx`.

## План подготовки

Кнопка «Составить план» на странице курса выбирает курс в правом сайдбаре. Если ни одна тема курса не начата, создание блокируется сообщением о необходимости первого прохождения.

Доступные параметры:

- срок: 3, 7, 14 или 30 дней;
- время: 20, 30, 45 или 60 минут в день.

`preparationPlan.js` сортирует темы от слабых к сильным. Число повторений рассчитывается как `1 + ceil((100 − прогресс) / 25)`, поэтому слабые темы появляются раньше и чаще. Один тематический блок условно занимает 20 минут, а число блоков на день определяется выбранным временем.

В сайдбаре отображаются активный курс, оставшиеся дни, ежедневное время и до 7 ближайших дней с темами и числом карточек. Кнопка «Продолжить план» открывает первую тему текущего дня.

## Настройки

Отдельная страница `/settings` содержит:

- светлую и тёмную темы;
- уменьшение анимаций;
- размер текста: мелкий, обычный или крупный;
- изменение никнейма и email;
- демонстрационную форму смены пароля;
- выход из локальной сессии;
- удаление локального аккаунта и данных.

Настройки применяются атрибутами `data-theme`, `data-reduce-motion` и `data-text-size` на элементе `html`. Уменьшение анимаций отключает CSS animation, transition и плавную прокрутку. Тёмная тема переопределяет поверхности, поля, сайдбары, карточки и фон переходов.

## Хранение в браузере

| Ключ | Формат и назначение |
| --- | --- |
| `practice-auth-v1` | Строка `true`, если локальная сессия активна. |
| `practice-user-v1` | JSON с `name` и `email`. |
| `practice-settings-v1` | JSON с `theme`, `reduceMotion` и `textSize`. |
| `practice-progress-v1` | JSON: идентификатор темы → процент `0–100`. |
| `practice-activity-v2` | JSON-массив последних ответов, максимум 2000 записей. |
| `practice-preparation-plan-v1` | JSON активного плана и его расписания. |

При первом запуске прогресс берётся из `data.js`, а журнал активности заполняется демонстрационными записями. Повреждённые или неподходящие данные заменяются безопасными начальными значениями.

Стили загружаются в порядке: база → каркас → общие компоненты → страницы → настройки → типографические акценты. Это важно для каскада тёмной темы и пользовательских параметров.

Основные точки адаптивности:

- при ширине до `1280px` постоянные сайдбары скрываются, а центральный контейнер занимает доступную ширину;
- при ширине до `700px` перестраиваются хедер, сетки страниц, карточки, формы и панели;
- отдельные компоненты дополнительно используют собственные точки `800px`, `560px`, `520px` и `420px`.

Левый и правый постоянные сайдбары имеют одинаковую ширину и симметричные внешние отступы. Центральная область ограничена шириной `1100px`, а на странице профиля — `900px`.

## Доступность и интерактивность

- у progress bar есть `role="progressbar"` и ARIA-значения;
- собственные dropdown используют роли `listbox` и `option`;
- переключатели используют `aria-pressed` или `role="switch"`;
- модальные панели имеют `role="dialog"` и `aria-modal`;
- модальные слои закрываются по backdrop и `Escape`;
- `useBodyScrollLock` блокирует прокрутку страницы и возвращает её после закрытия;
- в приложении есть skip-link «К содержимому»;
- для уменьшения движения учитываются настройка приложения и `prefers-reduced-motion`.

## Проверка

Штатная проверка проекта:

```sh
npm run build
```

`scripts/smoke.cjs` содержит расширенный браузерный сценарий: авторизация, восстановление сессии и настроек, маршруты, панели, dropdown, тренировка, аналитика, план, профиль, удаление данных и мобильное переполнение.

Playwright не указан в `package.json`, поэтому на чистой установке smoke-сценарий напрямую не запускается. Для его отдельного локального запуска требуется установленный пакет `playwright`, после чего используется команда:

```sh
node scripts/smoke.cjs
```

Сценарий создаёт тестовые PNG-файлы в корне проекта.

## Подключение backend

При подключении Spring Boot frontend потребуется:

1. добавить слой `src/api` для курсов, тем, аккаунта, прогресса, тренировок и планов;
2. заменить данные из `data.js` ответами API;
3. перенести сессию и пароль на backend;
4. хранить прогресс, ответы, активность и планы в базе данных;
5. заменить демонстрационную аналитику серверными агрегатами;
6. оставить в `localStorage` только интерфейсные настройки и безопасный кеш;
7. настроить возврат `index.html` для неизвестных клиентских URL.

Предполагаемые серверные сущности: пользователи, сессии, курсы, темы, карточки, прогресс по темам, ответы, тренировочные сессии, планы подготовки, дни плана и настройки пользователя.
