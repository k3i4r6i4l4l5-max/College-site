# Архитектура frontend

## Технологии

- React 19;
- React Router 7;
- Vite 6;
- обычный CSS;
- Playwright и `node:test`;
- mock-backend для работы без сервера.

## Слои

```text
Страницы и компоненты
        ↓
App и CatalogContext
        ↓
Доменные сервисы
        ↓
Единая функция request
        ↓
mockBackend или настоящий HTTP API
```

Страницы не вызывают `fetch` напрямую. Они используют сервисы авторизации, каталога, пользователя, тренировок, прогресса и планов подготовки.

## Точка входа

`src/main.jsx`:

1. читает сохранённые настройки интерфейса;
2. применяет их до первого рендера;
3. создаёт React root;
4. подключает `HashRouter`;
5. отображает `App`.

`src/App.jsx` загружает сессию и рабочие данные, хранит состояние верхнего уровня, связывает страницы с сервисами и формирует общий каркас приложения.

## Состояние

В `App` находятся:

- текущая сессия и пользователь;
- каталог;
- прогресс и история ответов;
- активная тренировка;
- курсы пользователя;
- план подготовки;
- настройки интерфейса.

Локальное состояние форм, панелей и переключателей остаётся внутри соответствующих компонентов.

## Обработка асинхронных состояний

`AsyncState.jsx` предоставляет загрузку, ошибку и пустое состояние. `SectionErrorBoundary.jsx` изолирует ошибки отдельных блоков, чтобы одна неисправность не приводила к падению всей страницы.

## Переходы

`PageTransition.jsx` отвечает за fade-переходы и вертикальную смену курсов. Изменение query-параметров не перемонтирует страницу, поэтому поиск и фильтры не теряют фокус.

## Текущее положение бизнес-логики

Пока backend не подключён, расчёт прогресса, формирование тренировок, планы подготовки и часть аналитики выполняются frontend mock-слоем. Интерфейс уже отделён от источника данных, поэтому эту логику можно постепенно переносить на сервер без полной переработки компонентов.
